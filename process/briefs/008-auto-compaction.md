# 008 — Auto-compaction

## Problem

Anthropic and OpenAI context windows fill. The TS proxy watches token usage and, at `TOKEN_WARNING_THRESHOLD` (default 160 000) starts pre-computing a structured summary; at `TOKEN_CLEAR_THRESHOLD` (default 180 000) it injects the summary and clears the conversation, replacing verbose exploration with a compact "preserved context" block that keeps the original goal, key decisions with reasoning, current state, and next steps. The point is that compaction without preserved reasoning leaves the agent dumber; compaction with preserved reasoning lets it continue.

kete implements the same thresholds, the same summary shape, and the same hand-off ("PRESERVED CONTEXT FROM THIS SESSION: …") that the TS code injects into the next request body. This is a mid-session mutation; raw-body discipline applies.

## Who is hurt

- Users on long sessions (refactors, feature builds spanning many turns). Manual `/compact` takes 2–3 minutes and burns tokens; auto-compaction is the win.
- The `tasks` row's `reasoning_trace` quality — if compaction drops a key decision, the captured task loses fidelity.

## Constraints

- Thresholds defaults: `TOKEN_WARNING_THRESHOLD=160_000`, `TOKEN_CLEAR_THRESHOLD=180_000`. Configurable via env.
- Pre-compute at warning, inject + clear at clear threshold. Pre-compute is best-effort; if it hasn't completed by clear threshold, fall back to a synchronous summary call before clearing.
- Summary shape:
  - `Original goal` (one line)
  - `Key decisions made` (bulleted; each with reasoning)
  - `Constraints discovered`
  - `Current state` (what's done, what's about to happen)
- Drop: verbose exploration, redundant file reads, superseded reasoning.
- The summary is generated by the same Haiku call (brief 011) that handles other extraction.
- After clear, the next request body has the summary as the first user message and the pre-clear conversation removed. Cache prefix is destroyed by definition; that's the cost of the operation.

## Success looks like

- A 50-prompt Claude Code session reaches `TOKEN_CLEAR_THRESHOLD`, the proxy injects a compaction, the agent resumes with the summary as context, and the captured `task` row's `reasoning_trace` includes the decisions from before the compaction.
- The pre-compute step at warning threshold completes within 5 s on a typical session; the clear step is sub-second once the summary exists.
- No silent data loss: every key decision present before compaction is present in either the summary or the persisted `task` row.

## Non-goals

- Replacing Anthropic's native `/compact`. We complement it; users can still trigger it manually.
- Custom prompts the user can edit. The summary template is the contract.
- Compaction for OpenAI's `/v1/responses` endpoint until the same need is observed there.
- Cross-session compaction. That's brief 010 (memory injection).

## Open questions

- `[adr]` Whether the compaction summary becomes a `task` row in its own right (TS captures it as part of the parent task; that's probably right).
- How to surface "compaction happened" to the user. A log line is the TS bar; consider a single `[grov] compacted at turn N (saved X tokens)` message printed to stderr.
